# AI summaries

shipnote can enrich `release.json` with audience-keyed prose generated by an LLM. AI is **opt-in** (`--ai`), **off by default**, and **never alters the Markdown** output — Markdown is rendered before AI runs, so disabling AI cannot change the canonical changelog body.

This doc covers the wire-level details: providers, models, output schema, caching, and prompt versioning. For a quick-start see the [README](../README.md#optional-ai-summaries).

## Why audience-keyed summaries?

PR links work for public repos. They don't work for **private repos with public consumers** (a private SDK that ships a public changelog page, an internal product whose `release.json` is mirrored to docs). For those teams the JSON output needs to *explain* what changed without the reader having to follow a link they can't open.

Three audiences are produced for each scope (release, change):

| Audience    | Voice                          | Length cap | Purpose                                         |
| ----------- | ------------------------------ | ---------- | ----------------------------------------------- |
| `developer` | Direct, technical              | ~30 words  | Inline release notes for engineers.             |
| `customer`  | Plain language, benefit-first  | ~30 words  | Public changelog / blog post / email digest.    |
| `migration` | Imperative, action-oriented    | ~60 words  | Upgrade guides; `"No migration required."` when no breaking change is present. |

Length caps are enforced in the prompt, not post-processed.

## Providers

| Provider  | `--ai-provider` | Wire format                | Auth                     | Default model              |
| --------- | --------------- | -------------------------- | ------------------------ | -------------------------- |
| Ollama    | `ollama`        | OpenAI `/v1` compat        | none (local)             | `llama3.2:1b`              |
| OpenAI    | `openai`        | OpenAI `/v1`               | `OPENAI_API_KEY`         | `gpt-4o-mini`              |
| Anthropic | `anthropic`     | Anthropic `/v1/messages`   | `ANTHROPIC_API_KEY`      | `claude-3-5-haiku-latest`  |
| Groq      | `groq`          | OpenAI `/v1`               | `GROQ_API_KEY`           | `llama-3.1-8b-instant`     |
| Custom    | `custom`        | OpenAI `/v1` compat        | optional `--ai-key`      | none — set `--ai-model`    |
| Auto      | `auto`          | first matching from above  | first available env var  | provider default           |

Auto-detect chain: `OPENAI_API_KEY` → `ANTHROPIC_API_KEY` → `GROQ_API_KEY` → local Ollama at `OLLAMA_HOST` (default `localhost:11434`).

### Custom-endpoint targets

Anything that exposes `POST /v1/chat/completions` and `GET /v1/models` works with `--ai-provider custom`:

- **OpenRouter** — `https://openrouter.ai/api/v1`
- **Together AI** — `https://api.together.xyz/v1`
- **DeepSeek** — `https://api.deepseek.com/v1`
- **Mistral La Plateforme** — `https://api.mistral.ai/v1`
- **Fireworks** — `https://api.fireworks.ai/inference/v1`
- **Anyscale, Perplexity** — provider docs.
- **Self-hosted**: vLLM, LM Studio, LocalAI — point `--ai-base-url` at the local server.

## Output schema

Each `Change` and the top-level `Summary` gain an `aiSummaries` block.

```json
{
  "schemaVersion": "1.0.0",
  "tag": "v0.2.0",
  "date": "2026-05-05",
  "summary": {
    "headline": "...",
    "aiSummaries": {
      "developer": {
        "text": "...",
        "model": "claude-3-5-haiku-latest",
        "promptVersion": "v1"
      },
      "customer":  { "text": "...", "model": "...", "promptVersion": "v1" },
      "migration": { "text": "No migration required.", "model": "...", "promptVersion": "v1" }
    }
  },
  "globalChanges": [
    {
      "type": "feat",
      "title": "...",
      "pr": { "number": 42, "url": "https://github.com/owner/repo/pull/42" },
      "aiSummaries": {
        "developer": { "text": "...", "model": "...", "promptVersion": "v1" },
        "customer":  { "text": "...", "model": "...", "promptVersion": "v1" },
        "migration": { "text": "...", "model": "...", "promptVersion": "v1" }
      }
    }
  ]
}
```

### Field reference

| Path                                 | Type   | Meaning                                                                |
| ------------------------------------ | ------ | ---------------------------------------------------------------------- |
| `aiSummaries.<audience>`             | object \| null | `null` means AI was off or that audience wasn't generated.       |
| `aiSummaries.<audience>.text`        | string | Prose summary. May be empty string if the model returned nothing usable. |
| `aiSummaries.<audience>.model`       | string | Exact model id reported by the provider — audit trail.                 |
| `aiSummaries.<audience>.promptVersion` | string | `"v1"` today. Bumps when prompts change.                             |

Consumers should treat any `aiSummaries.*` block as **advisory**. The deterministic Markdown body and the structural fields (`type`, `title`, `pr`, etc.) are the source of truth.

## Caching

Cache lives at `<repo>/.shipnote/cache/ai/<aa>/<sha256>.json` (already gitignored by `shipnote init`). Each entry stores the rendered prompt hash and the provider response.

**Cache key** = `sha256(provider | model | promptVersion | audience | scope | promptHash | canonicalFacts)`

- `provider` — the `Name()` returned by the Summarizer (`"openai"`, `"anthropic"`, ...).
- `model` — exact model string used in the request.
- `promptVersion` — `PromptVersion` constant in `internal/ai/types.go`.
- `audience` — `developer` | `customer` | `migration`.
- `scope` — `release` or a stable change id (e.g. `github-prs:42`).
- `promptHash` — sha256 of the rendered prompt text.
- `canonicalFacts` — sorted-key JSON of the structured facts passed to the template.

**Invalidation** is automatic and granular:

- Bump `PromptVersion` → all entries expire for that audience.
- Edit a single `.tmpl` file → only that audience's entries expire (its `promptHash` changes).
- Add a new fact field → only changes whose facts changed get re-summarised.
- Switch provider/model → fresh cache namespace; old entries remain on disk but unused.

Re-runs with no upstream changes are zero-network. The dogfooded warm run on this repo is ~0.1s.

## Prompts

Templates live in [internal/ai/prompts/](../internal/ai/prompts/) and are embedded at build time via `//go:embed`. Each template:

- Receives a single `{{ .Facts }}` slot containing the canonical-JSON fact set.
- Forbids inventing facts not present in the input.
- Hides PR numbers, commit SHAs, author logins, and file lists — those are added verbatim by the Markdown renderer, so AI doesn't need them and is more likely to hallucinate when given them.
- Constrains length explicitly.
- For `migration`: returns the literal string `"No migration required."` when no breaking change is present.

Prompt edits should be paired with a `PromptVersion` bump (or accept that templates with the same version drift their cache).

## Determinism contract

1. Markdown is rendered **before** `ai.Enrich` runs.
2. AI populates `Summary.AISummaries` and per-`Change.AISummaries` only.
3. JSON is rendered **after** AI runs and includes those fields.
4. If the provider is unreachable or returns an error, the failure is logged to stderr (via `--ai`'s logger hook) and AI is skipped. The release still ships.

This means:

- Toggling `--ai` never changes `CHANGELOG.md`.
- `shipnote generate --check` (drift detection) compares only the deterministic baseline; AI is not part of the drift check.
- Two runs with the same repo state, the same provider/model, and the same prompt version produce **byte-identical** AI text once the cache is warm. (Cold runs may differ if the provider is non-deterministic; `temperature=0` is set for OpenAI-shape providers as a second guard.)

## Failure modes

| Symptom                                       | Cause                                                       | Action                                                       |
| --------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------ |
| `shipnote: --ai-provider=X requires Y` on stderr | Missing API key for explicit provider.                    | Export the env var or pass `--ai-key`.                        |
| AI fields are `null` in JSON                   | Provider returned an error or `Available()` returned false. | Check stderr; the deterministic Markdown still shipped.       |
| Cache files growing unbounded                  | Long history of prompt edits.                               | Safe to `rm -rf .shipnote/cache/ai`; will repopulate.         |
| Same release, different AI text run-to-run    | Cold cache + non-deterministic provider.                    | Commit the cache to CI artifacts, or use a stable provider.   |

## CI usage

```yaml
- name: Generate release notes
  env:
    GROQ_API_KEY: ${{ secrets.GROQ_API_KEY }}
  run: |
    shipnote generate \
      --from $LAST_TAG \
      --to ${{ github.sha }} \
      --ai --ai-provider groq

- name: Upload release.json
  uses: actions/upload-artifact@v4
  with:
    name: release-json
    path: .shipnote/release.json
```

Cache the `.shipnote/cache/ai/` directory between runs to keep AI calls near-free.
